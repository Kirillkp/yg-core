# Выпуск версии пакета

Тег `vX.Y.Z` ставится только после прохождения всех шагов ниже.

## Выбор номера версии

| Тип | Когда | Требование |
|---|---|---|
| PATCH | исправление без изменения API | запись в CHANGELOG |
| MINOR | новая возможность, всё старое работает | запись + обновлённые модульные доки |
| MAJOR | ломающее изменение | **инструкция по переносу для игр** в записи версии |

Изменение формата сохранения без миграции не выпускается ни в каком типе версии.

## Шаги

1. **Подготовка записи.** Раздел `[Unreleased]` в `CHANGELOG.md` превращается в `## [X.Y.Z] - ГГГГ-ММ-ДД`. Создаётся `Documentation~/versions/vX.Y.Z.md` из шаблона: заполняются все разделы.
2. **Версия в манифесте.** В `package.json` пакета указывается `X.Y.Z`.
3. **Совместимость.** Обновляется `Documentation~/compatibility.md` (Unity, PluginYG2, схема сохранений).
4. **Модульные документы** затронутых модулей актуальны.
5. **Сборка стенда** (WebGL), версия пакета видна на экране стенда.
6. **Прогон стенда на Яндексе.** Загрузка черновика в консоль и прохождение `Docs/STAND_CHECKLIST.md`. Результат записывается в раздел «Проверено на стенде» записи версии (дата, окружение, результат).
7. **Проверка выпуска:**

   ```bash
   Tools/check-release.sh X.Y.Z
   ```

   Скрипт сверяет версию в `package.json`, запись в CHANGELOG, файл версии, заполненность разделов, наличие `.meta` у всех файлов пакета, проверки логики без Unity (`Tools/CoreChecks`), чистоту рабочего дерева и отсутствие такого тега. При любой ошибке тег ставить нельзя.
8. **Коммит и тег:**

   ```bash
   git tag vX.Y.Z
   ```

   Публикация тега в удалённый репозиторий делается владельцем.
9. **Обновление игр.** Для новых игр версия поднимается сразу, для живых игр оркестратор готовит изменение, а решение о применении принимает владелец.

## Что делает ответственный за шаг

| Шаг | Кто |
|---|---|
| 1–5, 7 | агент-разработчик, проверка агентом-QA |
| 6 | владелец (загрузка в консоль и чек-лист; около 10 минут) |
| 8, 9 | по решению владельца |
