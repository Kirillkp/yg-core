# Шаблоны игр

Два отдельных репозитория GitHub. Из шаблона создаётся новая игра, которая дальше живёт самостоятельно. Общее (пакет, оркестрация, общие файлы) приходит из `yg-core` по закреплённому тегу.

## Репозитории

| Репозиторий | Что это |
|---|---|
| `yg-template-empty` | Основа: проект Unity, который собирается и проходит стенд в консоли Яндекса, с подключённым пакетом, PluginYG2, оркестрацией и пустой игрой |
| `yg-template-roblox` | `yg-template-empty` плюс готовая оболочка «Roblox-подобной» игры: меню, магазин, настройки, пауза, результат, экономика, прогресс. Без геймплея, коллекции и контента «Обби» |

`yg-template-roblox` получает обновления основы через `git merge` тега `yg-template-empty`. Оболочка лежит в своих папках, поэтому конфликтов быть не должно.

## Структура `yg-template-empty`

```
AGENTS.md, CLAUDE.md          основной файл для всех агентов; CLAUDE.md только ссылка на него
Agents/                       из yg-core по тегу, только для чтения (правка запрещена, проверяется хешем)
Docs/
  AGENT_CONTEXT.md            компактный контекст игры (заполняется при создании)
  GAME_BRIEF.md               жанр, аудитория, правила, монетизация
  DECISIONS.md                решения игры
  specs/                      спецификации по темам
Tasks/
  QUEUE.md                    очередь: что сделано, что ждёт утверждения владельца
  _TASK_TEMPLATE.md           формат задачи
Packages/manifest.json        com.kirillpolosov.yg-core по тегу
Assets/
  PluginYourGames/            PluginYG2 v2.0092 (зафиксирован)
  YgCore/YandexBridge/        мосты, ставит установщик пакета (коммитятся)
  WebGLTemplates/YandexGames/ страница, загрузочный экран, качество
  link.xml
  Game/
    Scenes/Start2D.unity      стартовая сцена 2D
    Scenes/Start3D.unity      стартовая сцена 3D
    Scripts/                  GameApp: точка запуска (сервисы, пауза, звук, сохранения, локализация)
    Resources/WebQualitySettings.asset
  Editor/Build/               меню сборки WebGL в архив для консоли (из стенда)
tools/
  sync-core.sh <тег>          подтягивает Agents/ и общие файлы из yg-core, меняет тег пакета
  new-game.sh                 создаёт игру из шаблона (см. ниже)
  release.sh                  проверка и тег игры
template.json                 версия шаблона, тег yg-core, версия оркестрации
```

`GameApp` повторяет рабочую схему «Обби»: фабрики пакета, `PauseCoordinator`, `GameplayStateService`, сохранения через `ProgressionService`, локализация, звук. Игра дописывает свои схему прогресса, каталог строк и подписки звука.

## Добавка `yg-template-roblox`

```
Assets/Game/Shell/
  Screens/                    меню, магазин, настройки, пауза, результат (uGUI-префабы, лежат в сцене)
  Economy/                    монеты, награда за забег и за рекламу
  Store/                      каталог-заглушка, карточки, превью персонажа
  Progression/                схема прогресса-заглушка
  Audio/                      AudioDirector-наследник с типовыми звуками интерфейса
  Art/                        нейтральный стиль экранов (не из «Обби»)
```

**Правило интерфейса: что видно в Scene и Game, то и в игре.** Экраны это префабы uGUI, размещённые в сцене и настроенные в редакторе. Нельзя строить интерфейс кодом при запуске (как делает стенд): иначе в Scene он выглядит пустым и его не поправить глазами. Скрипты только подключают готовые экраны к сервисам. Проверка при приёмке экрана: скриншот сцены в редакторе совпадает со скриншотом собранной игры.

Коллекции (брейнроты) в оболочку не входят: это механика конкретной игры.

Оболочка выносится из «Обби» по задачам через оркестрацию. Внешний вид нейтрального стиля проходит процесс референсов через Codex (утверждает владелец).

## Создание новой игры

`tools/new-game.sh <имя> <шаблон> <тег>`:
1. копирует шаблон в новый репозиторий без истории;
2. переименовывает пространства имён, идентификатор приложения, название;
3. создаёт `Docs/GAME_BRIEF.md` и `AGENT_CONTEXT.md` по вопросам оркестратора;
4. **фиксирует имя поля сохранения** (`<имя>Storage`) в `Docs/DECISIONS.md` как неизменное после первого выпуска;
5. предлагает владельцу первый стенд: сборка WebGL и прогон в черновике консоли.

## Обновление игры

- Пакет: поднять тег в `manifest.json`, прогнать стенд, закоммитить мосты (`Assets/YgCore/YandexBridge`).
- Оркестрация и общие файлы: `tools/sync-core.sh <тег>`.
- Основа шаблона (для Roblox-игр): `git merge` тега шаблона.

## Версии

Шаблоны версионируются тегами (`v0.1.0`…), для каждой версии есть запись в `Docs/versions/` и записи в `template.json`. Тег шаблона создаётся только после прохождения стенда в консоли.

## Порядок работ

1. `yg-template-empty`: собрать из стенда и «Обби», пройти стенд, выпустить `v0.1.0`.
2. `yg-template-roblox`: вынос оболочки из «Обби» по задачам, референсы нейтрального стиля, выпуск `v0.1.0`.
3. Первая игра на шаблоне как проверка (критерий готовности: игра проходит стенд без правок пакета).

## Принятые решения владельца

1. 2D и 3D: две стартовые сцены в одном проекте (`Start2D`, `Start3D`), общие настройки URP.
2. Интерфейс оболочки на uGUI; экраны лежат в сцене и выглядят в редакторе как в игре.
3. Имена репозиториев: `yg-template-empty`, `yg-template-roblox`.
4. PluginYG2 хранится в шаблоне целиком (v2.0092).
5. В оболочку Roblox-шаблона коллекция не входит.
