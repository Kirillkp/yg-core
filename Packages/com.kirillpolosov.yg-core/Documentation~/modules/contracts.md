# Модуль: Контракты платформы

Сборка: `YgCore.Contracts` · Пространство имён: `YgCore.Contracts` · С версии: `v0.1.0` · Статус: перенесён из «Обби Потоп»

Зависимостей от других сборок нет, включая Core. Здесь только интерфейсы и простые неизменяемые типы данных.

## Зачем нужен

Описывает, что игра может попросить у платформы, не говоря как. Реализация подбирается отдельно: настоящая на PluginYG2 (`YgCore.Yandex`), мок для редактора (`YgCore.Mocks`) или заглушка «недоступно» (`YgCore.Factories`). Поэтому игровой код не зависит от Яндекса и работает в редакторе.

## Когда использовать

Всегда, когда игре нужна реклама, вход, покупка, сохранение, таблица лидеров, язык платформы, отметка готовности или аналитика. Игра принимает нужный интерфейс в конструкторе или поле и не знает, какая реализация за ним.

## Когда не использовать

- Не обращайтесь к PluginYG2 и Яндекс SDK напрямую вне `YgCore.Yandex`.
- Игровая логика (что выдать за рекламу, что делать после покупки) в контракты не входит.

## Результат операции

Операции возвращают `PlatformServiceResult` (или `PlatformServiceResult<T>` со значением). Обычные отказы не бросают исключений: проверяйте статус.

| Статус | Смысл |
|---|---|
| `Success` | Выполнено |
| `Denied` | Отказ платформы или игрока (смысл зависит от операции, см. ниже) |
| `Error` | Сбой. Причина в `Message` (для логов, игроку не показывать) |
| `PlatformUnavailable` | Платформы нет (редактор, локальный запуск, отключённый модуль) |

`Value` у результата с `T` имеет смысл только при `Success`.

## Интерфейсы

| Интерфейс | Назначение |
|---|---|
| `IAdsService` | Реклама с наградой и полноэкранная |
| `IAuthorizationService` | Вход игрока, профиль |
| `IPurchasesService` | Каталог, покупка, невыданные покупки, подтверждение выдачи |
| `ISaveService` | Хранилище «ключ → строка» |
| `ILeaderboardService` | Отправка результата, чтение топа |
| `ILocalizationService` | Язык платформы, выдача строк |
| `IGameReadinessService` | Отметка «игра готова» |
| `IGameplayLifecycleService` | Начало и конец геймплея, пауза от платформы |
| `IAudioFocusService` | Аудиофокус |
| `IAnalyticsService` | События аналитики |

Каждый интерфейс имеет `IsPlatformAvailable`: `false`, если платформы нет. В этом случае операции возвращают `PlatformUnavailable`.

## Что означают статусы для каждой операции

Смысл проверен по реализации на PluginYG2 из «Обби Потоп».

| Операция | Success | Denied | Error |
|---|---|---|---|
| `ShowRewardedAsync` | Реклама закрыта и награда засчитана. Можно выдавать награду | Награды нет: закрыли без награды, другая реклама уже идёт или реклама не готова. Награду не выдавать | Сбой показа или нет ответа 3 минуты |
| `ShowInterstitialAsync` | Показ состоялся | Реклама не показана (не готова или уже идёт другая) | Сбой показа или нет ответа 3 минуты |
| `SignInAsync` | Вход выполнен | После окна входа игрок остался гостем | Сбой |
| `PurchaseAsync` | Покупка прошла, в результате квитанция | Покупка не состоялась (отмена или отказ платформы) | Сбой или неверная квитанция |
| `ConsumeAsync` | Выдача подтверждена | | Сбой или таймаут |
| `LoadAsync` (сохранение) | Данные загружены. **Если данных по ключу нет, значение `null`, это тоже успех** | | Сбой загрузки |
| `SaveAsync` | Хранилище подтвердило запись | | Сбой или нет подтверждения |

## Правила, которые нельзя нарушать

### Реклама
Во время рекламы игра должна быть на паузе (причина `PauseReason.Ad` из модуля Core) и звук должен быть остановлен. События `AdStarted` и `AdFinished` для этого. `AdFinished` приходит только если реклама перед этим открывалась.

### Покупки: два шага
1. `PurchaseAsync` проводит оплату.
2. Игра выдаёт награду **и сохраняет её**.
3. Только после этого `ConsumeAsync(token)` подтверждает выдачу.

Если игра закрылась между шагами 1 и 3, при следующем запуске `RestorePurchasesAsync` вернёт невыданные покупки, и игра выдаст награду. Вызывать `ConsumeAsync` до выдачи нельзя.

### Сохранения: сбой не равен пустому сохранению
`LoadAsync` отличает «данных нет» (успех, `null`) от «не удалось загрузить» (`Error`). При `Error` нельзя создавать пустое сохранение и записывать его поверх: это стёрло бы прогресс игрока.

### Аналитика
Не влияет на игровую логику. Ошибка отправки игнорируется.

## Типы данных

| Тип | Назначение |
|---|---|
| `AuthorizationProfile` | Профиль игрока: `IsAuthorized`, `PlayerId`, `DisplayName`, `PhotoUrl`. `Guest()` создаёт профиль гостя. Поля никогда не `null` |
| `PurchaseProduct` | Товар: `Id`, `Title`, `Price`, `CurrencyCode`, `IsConsumable`, `DisplayPrice` (цена с валютой без дублирования) |
| `PurchaseReceipt` | Квитанция: `ProductId`, `Token`, `IsConsumed`, `PurchasedAt` |
| `LeaderboardEntry` | Запись таблицы: `PlayerId`, `DisplayName`, `Score` (`long`), `Rank` (как вернула платформа) |
| `AdPlacementKind` | `Rewarded`, `Interstitial` |
| События | `AdPlaybackEventArgs`, `AuthorizationProfileChangedEventArgs`, `LanguageChangedEventArgs`, `PlatformPauseChangedEventArgs`, `AudioFocusChangedEventArgs` |

## Подключение

Реализации выбирают фабрики (модуль Factories, будет перенесён). Игровой код получает нужный интерфейс:

```csharp
using System.Threading.Tasks;
using YgCore.Contracts;

// Игра зависит от интерфейса, а не от Яндекса.
public sealed class ReviveOffer
{
    private readonly IAdsService ads;

    public ReviveOffer(IAdsService ads) => this.ads = ads;

    public async Task<bool> TryReviveAsync()
    {
        var result = await ads.ShowRewardedAsync("revive");

        // Награду выдаём только при полном успехе: при Denied игрок рекламу не досмотрел.
        return result.IsSuccess;
    }
}
```

## Чего делать нельзя

- Обращаться к PluginYG2 или JS-мосту вне `YgCore.Yandex`.
- Выдавать награду за рекламу при любом статусе кроме `Success`.
- Считать `Error` загрузки пустым сохранением.
- Вызывать `ConsumeAsync` до выдачи и сохранения награды.
- Показывать игроку `Message` результата.

## Как проверить на стенде

Секции «Реклама», «Покупки», «Сохранение», «Авторизация», «Лидерборд», «Язык», «Готовность» (появятся вместе со стендом и реализацией на PluginYG2). Сами интерфейсы без реализации проверить нечем: их компиляция и корректность документации проверяются командой `dotnet run --project Tools/CoreChecks`.
