# Модуль: Web-качество

Сборка: `YgCore.WebQuality` · Пространство имён: `YgCore.WebQuality` · С версии: `v0.1.0` (пока в разделе Unreleased) · Статус: перенесён из «Обби Потоп», правила проверены вне Unity (в Unity и на устройствах не проверен)

Зависимостей от других сборок пакета нет.

## Зачем нужен

В браузере игра запускается и на мощном компьютере, и на слабом телефоне. Один уровень качества графики не подходит обоим. Модуль при запуске WebGL-сборки сам выбирает уровень качества для компьютера или для телефона и задаёт частоту кадров. Делать ничего в коде не нужно.

## Как это работает

1. При старте WebGL-сборки (до загрузки первой сцены) модуль загружает файл настроек `WebQualitySettings` из любой папки `Resources`.
2. Через маленький JavaScript (`YgCoreWebQuality.jslib`) определяет, мобильное ли устройство.
3. Включает уровень качества `Web Mobile` или `Web Desktop` (имена из настроек) и выставляет частоту кадров.

В редакторе и на других платформах модуль ничего не делает.

### Как определяется «мобильное устройство»

- Если страница игры (WebGL-шаблон) определила объект **`window.YgWebQuality`** со свойством `isMobile`, берётся оно: страница знает лучше (например, учитывает размер экрана).
- Иначе запасной вариант по строке браузера: Android, iPhone, iPad, iPod, а также iPad в режиме «Macintosh» (у него есть несколько точек касания). Компьютеры с сенсорным экраном телефонами не считаются.

### Частота кадров

`-1` (по умолчанию) означает, что частоту выбирает браузер: он лучше знает, какая подходит устройству. Положительное число просит явный предел кадров в секунду. Ноль и отрицательные значения превращаются в `-1`.

## Подключение

1. Создайте уровни качества в **Project Settings / Quality**: по умолчанию ищутся `Web Desktop` и `Web Mobile` (имена можно изменить в настройках). Уровни должны быть включены для WebGL.
2. Создайте файл настроек: **Assets / Create / YgCore / Web Quality Settings**. Положите его в папку **`Resources`** и оставьте имя **`WebQualitySettings`**.
3. Укажите в файле имена уровней и частоту кадров.
4. По желанию определите на странице игры `window.YgWebQuality = { isMobile: ... }` (в `index.html` или скрипте шаблона).

## Правила

- Файл настроек должен называться `WebQualitySettings` и лежать в папке `Resources`.
- Имена уровней качества в файле должны точно совпадать с именами в Project Settings (регистр важен). Если уровня нет в сборке (не создан или отключён для WebGL), остаётся уровень по умолчанию и пишется предупреждение в консоль браузера.
- Если файл настроек не найден, остаётся уровень по умолчанию, пишется предупреждение.

## Чего делать нельзя

- Переименовывать файл настроек: модуль ищет именно `WebQualitySettings`.
- Вызывать `QualitySettings.SetQualityLevel` и `Application.targetFrameRate` из игры в WebGL: они перетрут выбор модуля.

## Как проверить

Без Unity: `dotnet run --project Tools/CoreChecks`. Для веб-качества там проверки выбора уровня (компьютер и телефон, нет уровня, пустые имена, регистр) и нормализации частоты кадров, плюс компиляция ветки WebGL (`dotnet build Tools/CoreChecks -p:WebGLCompile=true`). Мутация (перепутать компьютер и телефон) ловится.

На стенде: в консоли браузера строка «Веб-графика: ...» с ожидаемым уровнем на компьютере и на телефоне (в режиме эмуляции и на реальном устройстве). **Не проверено:** настоящий выбор уровня в Unity, автозапуск при старте сборки и JavaScript-определение мобильного устройства.

## Отличия от «Обби Потоп»

- Пространство имён `YgCore.WebQuality`, пункт меню `YgCore/Web Quality Settings`.
- Логика выбора уровня и частоты кадров вынесена в чистые функции (`WebQualityPolicy`) и проверяется тестами.
- JavaScript-функция `ObbyWebIsMobile` стала `YgCoreWebIsMobile`, объект страницы `window.ObbyWebQuality` стал `window.YgWebQuality`. Для «Обби» страница и `quality.js` в WebGL-шаблоне переименовываются (см. раздел «Переключение Обби»). Запасной вариант определения устройства сохранён.
- Предупреждения и комментарии на русском.
